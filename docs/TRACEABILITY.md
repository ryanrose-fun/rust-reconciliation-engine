# Report traceability

Each successful engine call creates a random UUID report_id and UTC generated_at timestamp, plus engine_version, rules_version, fingerprint_format and a reference for each source. API callers may supply internal/provider source labels.

The source references contain a record count and SHA-256 hash. Fingerprint format `payment-json-v1-input-order` hashes compact UTF-8 JSON generated by Serde from the validated Payment array. Field order is id, currency, amount_minor, status. Input array order and nonblank ID whitespace are preserved. JSON indentation and incoming object property order do not affect this normalized representation. Labels are excluded from the hash. The format version must change if these serialization rules change.

The rules version is 2: compare exact IDs, reject duplicate IDs per source, compare amount/status/currency independently, preserve each source's evidence, and count each nonmatching payment once.

To reproduce a finding, retain both original snapshots, their normalized hashes, engine/rules versions, and the report. Re-running the same ordered snapshots produces the same findings and fingerprints, but a new report ID and timestamp. Hashes detect changes when checked against retained source data; they do not authenticate the original source or provide a digital signature.

The API does not save reports, sign them, or maintain append-only audit storage. The CLI writes a report file and replaces its requested output path. Company retention, access control, tamper-evident storage, and snapshot timing remain deployment responsibilities. Optional labels are supplied by the caller and are not independently verified.
